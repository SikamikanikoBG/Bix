# Bix · софтуер

Софтуерът на Bix има две части, както в blueprint-а:

- **Устройство** (`bix device`) записва в залата, пази записа локално, докато има мрежа, и го качва. Работи на лаптоп с Windows, на Ubuntu и на Raspberry Pi 5 с reSpeaker XVF3800.
- **Сървър** (`bix server`) прави текста, разпознава кой говори и пише минутите. Има и уеб портал за организацията: зали, устройства, хора, потребители и роли, съхранение и одит. Пуска се в Docker в регион на ЕС или в частен облак.

Пълната спецификация е в [SPEC.md](SPEC.md).

```
 зала                                         облак в ЕС / частен облак
┌───────────────────────────┐   HTTPS 443   ┌──────────────────────────────────────────┐
│ bix device                │  (mTLS опц.)  │ bix server                               │
│  микрофон → VAD → откъси  │ ────────────► │  device API → опашка → worker            │
│  локален буфер (2 ч)      │ ◄──────────── │   звук → реч→текст → говорещи → минути   │
│  панел / лице на дисплея  │  команди,     │   → имейл / Microsoft 365                │
│  LED пръстен, радар       │  политики     │  портал (SSO, роли, одит, GDPR)          │
└───────────────────────────┘               └──────────────────────────────────────────┘
```

## Бърз старт на този лаптоп

```powershell
cd Bix\software
powershell -ExecutionPolicy Bypass -File deploy\windows\start-bix.ps1           # първи път инсталира всичко
powershell -ExecutionPolicy Bypass -File deploy\windows\start-bix.ps1 -Install  # + стартиране при вход
```

Или ръчно: `uv venv; uv pip install -e ".[local-stt]"; .venv\Scripts\bix dev`.

`bix dev` пуска сървъра и устройството на една машина:

| | |
|---|---|
| Портал | http://127.0.0.1:8710. При първо пускане се създава администратор; паролата се показва веднъж и се записва в `%LOCALAPPDATA%\Bix\server\first-admin.txt`. |
| Екранът в залата | http://127.0.0.1:8711. Същият екран е на 7" дисплея на устройството: срещата сега и следващите, „Започни“, „Попитай Bix“, ⭐, пауза, край. |
| Виртуално устройство | http://127.0.0.1:8711/sim. 3D моделът на корпуса Bix CRT с истинския екран вътре, плюс радар, бутон Mute и светлините на микрофона. Така се пробва целият ден без хардуер. |
| Данни | `%LOCALAPPDATA%\Bix\server` (база, записи, модели) и `%LOCALAPPDATA%\Bix\device` (буфер) |

Настройката на този лаптоп е в `%LOCALAPPDATA%\Bix\server\server.toml`:

- **Реч → текст:** Whisper на ArDi (`http://<whisper-server>:9110`, през Tailscale). Ако ArDi не отговаря, текстът се прави на лаптопа с faster-whisper large-v3-turbo, горе-долу в реално време.
- **Минути:** Qwen 3.8 27B на vader през vLLM (`http://<vllm-server>:8000/v1`). Ако vader не отговаря, се ползва Claude през Claude Code CLI.

Запис от телефон, Teams или Zoom се обработва с „Качи запис“ в портала.

## Един обикновен ден

Хората ползват само екрана в залата и имейла. Порталът е за ИТ и за редки корекции.

1. **Календарът на залата** идва от резервациите в портала (Зали → Календар), от таен iCal адрес на Google Calendar или Outlook (без регистрация на приложение), или от Microsoft 365. Екранът показва срещата сега и следващите.
2. **Влизате и натискате „Започни „Седмичен преглед““.** Темата, организаторът и участниците идват от календара. Ако никой не натисне, а в залата се говори, екранът пита „Започва ли среща?“. Bix никога не записва сам.
3. **По време на срещата:** „Попитай Bix“ с готови въпроси (*Какво решихме досега?*, *Кой какво ще прави?*, *Последните 10 минути*, *Какво пропуснах?*) или на глас с „Задръжте и питайте“. „Запиши задача: …“ влиза в минутите. ⭐ маркира важен момент.
4. **Краят:** „Край“ или автоматично, но винаги с брояч и „Продължаваме“: тишина, празна зала, свършило време по календар или следващата среща в залата започва.
5. **След това** екранът казва на кого отиват минутите, а минутите идват сами по имейл (организатор, участници, разпознати по глас хора, получатели на залата). На началния екран пише дали последната среща е стигнала до хората.

Лицето на екрана е LED матрица; в Настройки има още 8 вида.

## Устройство на Raspberry Pi / Ubuntu

```bash
git clone https://github.com/SikamikanikoBG/Bix && cd Bix/software
sudo deploy/linux/install-device.sh            # агент + панел
sudo deploy/linux/install-device.sh --screen   # + екранът на 7" дисплея (Chromium в киоск, cage)
sudo bix-device enroll --server https://bix.firma.eu --code XXXX-XXXX-XXXX
journalctl -u bix-device -f
```

Кодът се взима от портала: **Устройства → Регистрирай устройство**. Важи до 24 часа и е за еднократна употреба. На Pi скриптът сам слага `input_device = "XVF3800"` и радара LD2410C на UART0. Какво да се добави в `config.txt` е в `deploy/linux/config.txt.snippet`.

## Сървър в облака

```bash
cd Bix/software/deploy/docker
cp .env.example .env        # домейн, ключове за Azure Speech / Claude, SSO, Microsoft 365
docker compose up -d        # Bix + PostgreSQL + Caddy (TLS)
docker compose exec bix bix server admin --email admin@firma.bg
```

Доставчиците се избират в `server.toml` или с променливи `BIX_*` (виж `deploy/server.example.toml`):

| Стъпка | Доставчици | Данните остават |
|---|---|---|
| Реч → текст | `azure` (bg-BG, разделя говорещите), `whisper_http` (собствен GPU сървър), `faster_whisper` (на самия сървър) | ЕС регион на Azure / вашия хардуер |
| Кой говори | `sherpa` (pyannote 3.0 + TitaNet, локално), гласови профили със съгласие, имена от разговора | сървъра |
| Минути | `anthropic` (Claude Opus 5.5), `bedrock` (eu-central-1), `vllm` (собствен модел), `claude_cli` | Anthropic / AWS ЕС / вашия хардуер |
| Изпращане | Microsoft Graph (`sendMail`) или SMTP | |
| Хранилище | диск или S3 с KMS ключ на клиента | |

Всеки доставчик може да има резервен (`fallback_provider`).

## Команди

```
bix dev                         сървър + устройство на една машина
bix server [--no-worker]        портал, API на устройствата, обработка
bix server worker               само обработка (мащабира се отделно)
bix server admin --email X      администратор от командния ред
bix server code --room "Витоша" код за регистрация на устройство
bix device [--face]             агентът на устройството
bix device enroll --server URL --code КОД
bix device mics                 списък с микрофони
bix doctor                      проверка на настройките и доставчиците
bix eval reference.txt transcript.json   WER/CER (критерият на Фаза 1: под 15%)
```

## Тестове

```bash
uv pip install -e ".[dev]"
pytest                                       # 16 теста: целият път през API-то, роли, CSRF, съхранение, GDPR
python tools/make_test_meeting.py out/       # синтетична среща на български с 4 гласа и еталонен текст
```

Микрофонът може да е файл (`input_device = "file:out/meeting.wav"`). Така целият път на устройството се пуска без хора в залата.

Измерено на 11.10.2026 със синтетичната среща от 105 s, 12 реплики и 4 гласа:

| | Време | Качество |
|---|---|---|
| Whisper на ArDi (RTX 3090) | 10,5 s | WER 12,6% |
| faster-whisper large-v3-turbo на лаптопа (Ryzen 7 5825U, CPU) | 108 s | WER 7,6% |
| Говорещи (sherpa, лаптоп) | 10–14 s | 3 от 4. Два гласа, направени от един и същ TTS глас с друга височина, се сливат. С реални хора трябва да се провери във Фаза 1. |
| Минути, Qwen 3.8 27B на vader | 10–12 s | всички решения, задачи и срокове; 2 имена, извадени от разговора |
| Минути, Claude Opus 5.5 | 21 s | същото, по-стриктно какво е „решение“ |
| Цялата среща: устройство → минути | ~30 s след края | |
